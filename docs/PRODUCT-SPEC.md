# Project Factory — Product Specification

## Promise

**You describe it. We build it.**

A customer uses a phone or browser to describe a software project. The service converts the request into a scoped package, builds it through the Project Factory, verifies the result, and delivers the requested output.

## Customer does not need our tools

The customer does not need:

- A coding environment
- Git knowledge
- An AI coding subscription
- An API key
- Local model installation
- Vercel configuration

GitHub and Vercel are internal build/deployment tools unless the customer explicitly chooses a technical handover.

## What we can deliver

The factory is output-oriented. A request can produce:

- Website/web app
- API/backend
- Android source plus APK/AAB when the build environment supports it
- iOS source/archive/build when the required Apple signing/build environment is available
- SaaS/internal tool
- Automation/integration
- Source code and deployment documentation

## Ownership and hosting

Every paid project chooses one delivery mode:

### Managed

We host and maintain the agreed product. The customer receives the live product and support terms.

### Handover

The customer receives the source and production assets in customer-controlled accounts where platform rules allow it.

### Hybrid

We operate the product while customer ownership is established for critical production assets where practical.

The factory never assumes that GitHub, Vercel, app-store accounts, domains, databases, payment accounts, or third-party resources are transferable. The project contract records what is actually owned, hosted, transferred, or maintained.

## Factory acceptance

A project is not delivered because an agent says it is complete. Delivery requires acceptance criteria, test evidence, verification evidence, artifact evidence, ownership/delivery confirmation, and a final checkpoint.

## Pricing principle

Start with a tightly scoped package. Price is configurable after measuring actual inference, execution, hosting, and support costs. The zero-cost-first rule applies before revenue.

## Business metric

Track contribution margin per successful project:

`customer price - model/inference cost - execution/storage/deployment variable cost - support cost`

The goal is positive margin at the lowest practical package price.
