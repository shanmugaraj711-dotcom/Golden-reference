# First Customer — Delivery SOP

## Objective

Get the first paying customer while keeping quality high and spending at ₹0 unless the owner explicitly approves otherwise.

## Flow

1. Customer describes the project.
2. Capture requirements and acceptance criteria.
3. Classify scope as starter, pro, or custom.
4. Quote a fixed package price.
5. Receive payment before build work begins.
6. Create a dedicated project workspace/repository.
7. Build using the current approved AI tooling.
8. Run build, tests, verification, and security checks.
9. Deploy a preview.
10. Customer reviews the agreed scope.
11. Fix in-scope issues.
12. Deliver repository/preview and close the project.
13. Record revenue, variable cost, hours, defects, and customer feedback.

## Starter package guardrails

The first paid offer must be tightly scoped. Do not promise unlimited features or unlimited revisions at a low price. Anything outside the agreed acceptance criteria becomes a new quote.

## Quality gate

Do not deliver based only on an agent's statement that the project is complete. The project must have reproducible acceptance evidence.

## Zero-cost rule

Before first revenue, prefer free/open-source tooling and existing free quotas. Do not purchase compute, model APIs, subscriptions, or infrastructure solely to prepare for hypothetical demand.

## First-customer success metric

A successful first project means:

- customer paid;
- agreed scope delivered;
- preview/production result works;
- no known critical defect at handoff;
- actual variable cost recorded;
- customer feedback captured.
